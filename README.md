# CarLog

CarLog хранит автомобили, заправки, расходы, обслуживание и напоминания в PostgreSQL. Сервер и настольное приложение написаны на C++17. Telegram-бот написан на Python и работает отдельным процессом.

## Windows без Docker

Откройте `client/CMakeLists.txt` в Qt Creator с комплектом Qt 6.11.1 Desktop MinGW.
Для установки на другие ПК собирайте установщик из PowerShell. Установщик кладёт Qt
и библиотеки MinGW рядом с программой и создаёт ярлык. Целевая система — Windows 10/11 x64.

### Один компьютер для сервера и бота

Распакуйте проект в папку с латинским путём, например `C:\Users\sasam\CarLogNative`.
На серверном ПК нужны компоненты Qt Tools (MinGW 13.1, CMake, Ninja), Git с
подготовленным vcpkg, PostgreSQL 17 и Python 3.11. Для распознавания чеков
установите Tesseract с языками rus и eng, а его папку укажите в
`CARLOG_TESSERACT_DIR` в .env либо добавьте её в PATH.

Один раз подготовьте vcpkg, если его ещё нет:

```powershell
git clone https://github.com/microsoft/vcpkg.git C:\vcpkg
& C:\vcpkg\bootstrap-vcpkg.bat -disableMetrics
```

Из папки CarLogServer:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\native\build-server.ps1 -VcpkgRoot C:\vcpkg
powershell -NoProfile -ExecutionPolicy Bypass -File .\native\setup-bot.ps1
```

Скрипт собирает C++ сервер тем же MinGW, который поставляется с Qt, в
`build\native-server\carlog-server.exe`. При ручной сборке можно открыть
`cpp/CMakeLists.txt` в Qt Creator и указать те же параметры CMake, что в скрипте.

В локальной PostgreSQL создайте роль `carlog` с паролем и базу `carlog` с владельцем
`carlog`. Сохраните свой действующий .env рядом с README и обновите пароль базы при
необходимости. Для новой установки скопируйте .env.example, укажите пароль PostgreSQL,
два разных случайных секрета и токен своего Telegram-бота.
Для внешней базы можно задать `CARLOG_DATABASE_URL` в .env. Значения в .env пишите
в формате `ИМЯ=значение` без комментариев справа.

Откройте `native\start.cmd`. Он подготовит схему, запустит API и после проверки
доступности запустит бота. Держите окно открытым. При временном сбое Telegram бот
повторит запрос. Если процесс бота завершится, скрипт запустит его снова.
Журналы находятся в `build\native-logs`. Ctrl+C останавливает оба процесса.
Для теста API без Telegram вызовите `native\start.cmd -NoBot`.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

### Перенос существующих аккаунтов и привязок Telegram

Если база раньше была в Docker, одного .env недостаточно: перенесите её данные.
Сначала остановите старый API и бота, чтобы они не меняли записи. Базу в контейнере
оставьте включённой на время резервного копирования. Из старой папки проекта:

```powershell
docker compose -p carlogserver stop bot server
docker compose -p carlogserver exec -T db pg_dump -U carlog -d carlog -Fc -f /tmp/carlog.dump
$dbContainer = docker compose -p carlogserver ps -q db
docker cp "${dbContainer}:/tmp/carlog.dump" .\carlog.dump
```

Восстановите резервную копию **в пустую нативную базу carlog** до запуска
`native\start.cmd`. Команда запросит пароль. Укажите фактический путь к
`pg_restore.exe`, если PostgreSQL установлен в другое место.

```powershell
& "C:\Program Files\PostgreSQL\17\bin\pg_restore.exe" -h 127.0.0.1 -U carlog -d carlog --no-owner --no-privileges --single-transaction .\carlog.dump
```

Сохраните исходную базу до проверки входа, записей и существующей привязки Telegram.
Держите только одну работающую копию бота на этот токен. PostgreSQL и API по
умолчанию слушают локально. Для подключения других устройств настройте
постоянный HTTPS-прокси к `http://127.0.0.1:8000`. Клиенты обращаются к нему по
одному адресу, PostgreSQL остаётся закрытой.

## Настольное приложение

Интерфейс перенесён из присланного проекта 341/CarLog. Окно входа содержит логин, пароль, сохранение логина и кнопки входа, регистрации и восстановления. Созданный аккаунт открывается сразу, его журнал пустой. Пароль на компьютере не сохраняется.

Для уже установленного у вас Qt 6.11.1 MinGW откройте PowerShell в папке CarLogServer:

```powershell
$env:Path = "C:\Qt\6.11.1\mingw_64\bin;C:\Qt\Tools\mingw1310_64\bin;" + $env:Path
New-Item -ItemType Directory -Force build\client
Set-Location build\client
& "C:\Qt\6.11.1\mingw_64\bin\qmake.exe" -spec win32-g++ ..\..\client\client.pro
& "C:\Qt\Tools\mingw1310_64\bin\mingw32-make.exe" -j2
& "C:\Qt\6.11.1\mingw_64\bin\windeployqt.exe" --release .\release\carlog.exe
Copy-Item ..\..\client\carlog.ini.example .\release\carlog.ini
.\release\carlog.exe
```

Используйте новую распакованную папку проекта, чтобы старые объектные файлы не попали в сборку.

На Linux с установленными Qt Widgets, Qt Network, qmake и компилятором C++17:

```bash
make desktop
cp client/carlog.ini.example build/client/carlog.ini
./build/client/carlog
```

Для Visual Studio с комплектом Qt MSVC можно открыть папку `client` как CMake-проект и задать `CMAKE_PREFIX_PATH` на установленный Qt MSVC. Комплект MinGW собирается командами выше.

## Установщик для Windows

Когда общий HTTPS-адрес уже отвечает на /api/health, выполните из папки проекта
с установленным Inno Setup:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\installer\build.ps1 -ServerUrl "https://carlog.example.org"
```

Подставьте свой адрес. Результат — `build\installer\CarLogSetup.exe`.
Установщик обновляет адрес сервера в carlog.ini, в том числе поверх старого
localhost. Установите его на тестовом Windows 10/11 x64 без Qt и проверьте вход в
тот же аккаунт. Для сборки только для ПК с сервером есть явный параметр `-LocalOnly`.

## Адрес общего сервера задаёт разработчик

Перед передачей приложения пользователям задайте адрес в `carlog.ini` рядом с исполняемым файлом:

```ini
[server]
url=https://адрес-вашего-сервера
```

Сам файл не содержит секретов. Поля для ввода адреса в интерфейсе нет. Вместе с исполняемым файлом и Qt-библиотеками передавайте пользователям готовый `carlog.ini`. На всех компьютерах должен быть один адрес. Пользователь создаёт аккаунт и затем входит в него с другого компьютера тем же логином и паролем.

По умолчанию используется `http://127.0.0.1:8000` для локальной разработки. Общий публичный сервер в проекте не размещён. Для входа с других компьютеров нужно развернуть сервер из предыдущего раздела и настроить HTTPS. Для технической проверки можно временно переопределить адрес переменной окружения `CARLOG_SERVER_URL`.

## Привязка Telegram и фото чека

1. Войдите и добавьте автомобиль.
2. Откройте **Telegram и аккаунт → Получить код**. Отправьте показанную команду `/link КОД` боту в личном чате.
3. Сфотографируйте чек АЗС целиком и отправьте фотографию. Tesseract извлечёт текст. Бот покажет объём, цену за литр и итоговую сумму. При необходимости исправьте поля.
4. Подтвердите данные, выберите авто и введите пробег или `0`. Заправка сохранится в общей базе. В открытой вкладке настольного клиента она появится при очередном обновлении (до 10 секунд).

Повторное сохранение того же Telegram-фото для той же машины и чата вернёт существующую запись. Если OCR ошибся, проверьте цифры перед подтверждением. Команда `/fuel 40.5 59.9 Лукойл` позволяет ввести заправку вручную.

Бот проверяет напоминания раз в минуту. Он отправляет первое сообщение за `CARLOG_REMIND_DAYS` дней и второе в день события. Если сервер был выключен, просроченное невыполненное напоминание попадёт в отправку при следующем запуске. Используйте один экземпляр бота на сервер. Доставка повторяется при ошибке, поэтому при сбое между отправкой и подтверждением Telegram может показать повторное сообщение.

## Перенос данных из SQLite

Импортёр понимает схему SQLite из CarLogServer. Сделайте резервную копию старой базы после остановки старого сервера. Импорт выполняется одной транзакцией в **пустую** PostgreSQL. Переносятся аккаунты, автомобили, записи, категории и привязки Telegram. Старые сеансы и коды восстановления нужно получить заново. При первом входе сохранённый старый хеш пароля обновляется.

```bash
docker compose stop server bot
docker compose up -d --wait db
docker compose run --rm --no-deps -v "$PWD/backup.sqlite3:/tmp/old.sqlite3:ro" server \
  sh -c 'carlog-server --init && carlog-import /tmp/old.sqlite3'
docker compose --profile telegram up -d
```

Права на чтение файла должны позволять контейнеру прочитать резервную копию. Если старая программа использует другую структуру SQLite, сначала сопоставьте её схему с `cpp/schema.sql`.

## Запуск на Linux без Docker

Для сервера нужны `g++`, `make`, `pkg-config`, заголовки и библиотеки PostgreSQL, OpenSSL, libcurl и SQLite. PostgreSQL можно подключить с другой машины. Укажите строку libpq в `CARLOG_DATABASE_URL`, секреты из `.env` и `PGTZ` с часовым поясом. По умолчанию API слушает `127.0.0.1:8000`.

```bash
make -j2
./build/carlog-server --init
./build/carlog-server
```

Для бота в другом терминале нужны Python 3.9+ и установленный Tesseract с языками `rus` и `eng`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
set -a
source .env
set +a
python run_bot.py
```

При размещении бота отдельно задайте `CARLOG_SERVER_URL` с HTTPS-адресом API и тот же `CARLOG_BOT_SECRET`. Опциональные параметры `CARLOG_SMTP_*` включают восстановление по почте. Восстановление через Telegram доступно после привязки. Диалог восстановления есть в настольном клиенте.

## Исходники и проверки

- `cpp/` — модули API (вход, автомобили, журнал, статистика, Telegram, восстановление), схема PostgreSQL.
- `client/` — Qt-клиент с исходным оформлением. Окно входа, навигация, карточки, журнал, формы и сетевой доступ разнесены по файлам. Запросы асинхронные.
- `bot/` — диалог с Telegram, OCR и доставка уведомлений. Бот обращается только к API.
- `tests/` — тесты бота и сквозная проверка API. Используйте отдельную тестовую БД.

```bash
python -m unittest discover -s tests -t .
CARLOG_BOT_SECRET=секрет_тестового_сервера python -m tests.integration
```

Ошибка запроса возвращается в конкретный раздел. Если модуль API не настроен, `/api/health` показывает его в `failed_modules`. Общий сбой PostgreSQL влияет на все разделы, которым нужны данные. Бот и клиент работают отдельными процессами.

В `vendor/` зафиксированы cpp-httplib 0.28.0 и nlohmann/json 3.12.0. Тексты лицензий находятся рядом с заголовками.

Проверка интерфейса находится в `tests/client_smoke.cpp`. Её можно собрать через `client/CMakeLists.txt` с `CARLOG_BUILD_SMOKE=ON`. Она создаёт тестовый аккаунт, проверяет пустой журнал и добавление автомобиля и заправки через интерфейс. Укажите `CARLOG_TEST_URL` тестового сервера. Тест требует отдельную тестовую базу.

## Обновление кнопок, форм и импорта

Бот показывает меню с кнопками. Первое подключение можно выполнить по ссылке из настроек приложения. Для этого задайте в .env CARLOG_BOT_USERNAME с именем вашего бота без @ и пересоздайте сервер. При отсутствии имени бота используйте кнопку привязки в боте и вставьте шесть цифр из приложения один раз.

Ручное добавление заправки проходит по шагам. Исправление чека начинается с выбора поля. Выбор авто, пропуск пробега, подтверждение, отмена, просмотр напоминаний и отметка выполнения доступны кнопками. Фото чека и числа пользователь отправляет сам.

В формах автомобиля и записей добавлены списки с возможностью своего значения. Марка подсказывает модели, год и объём двигателя выбираются из списка. Категории и типовые операции обслуживания выбираются из списков. Для дат доступны календари. Цена и литры рассчитывают сумму; пробег подсказывается из выбранного авто.

В Настройках рядом с экспортом появился импорт JSON. Принимается файл, созданный кнопкой «Создать резервную копию» этой версии CarLog (format=1, cars, records). Размер до 900 КБ. Импорт добавляет данные в текущий аккаунт, сопоставляет новые номера автомобилей, сохраняет статус напоминаний. Ошибка откатывает весь импорт. Повтор того же файла не создаёт дубли. CSV в этой версии предназначен для экспорта.

Управление аккаунтом разделено на профиль и Telegram. Доступны изменение email и пароля, подключение и отвязка бота. После изменения пароля на других устройствах нужно войти заново.

При обновлении сохраните свой .env и базу. Пересоберите сервер и установщик
из новой папки проекта, затем перезапустите `native\start.cmd`. Схема базы
обновится при запуске.

Для SMTP на порту 465 сервер использует SMTPS. На порту 587 используется SMTP
с обязательным STARTTLS. При изменении порта в .env перезапустите native/start.cmd.
Журнал сервера содержит код ошибки libcurl без логина, пароля и кода восстановления.

## Android и iOS

В клиент добавлен мобильный режим Qt Widgets. Он включается автоматически на Android/iOS. Используются те же API, аккаунты, база и Telegram-бот. Вход отображается одной колонкой, навигация находится сверху, формы и страницы прокручиваются. Широкие таблицы журнала имеют горизонтальную прокрутку.

Для телефона нужен доступный извне HTTPS-адрес сервера. Адрес 127.0.0.1 на телефоне относится к самому телефону. Укажите адрес при сборке через CMake-параметр CARLOG_API_URL. В мобильный пакет он включается автоматически, пользователю не нужно редактировать ini. Если адрес не задан, мобильная CMake-конфигурация остановится с объяснением.

Официальные руководства:
https://doc.qt.io/qt-6/deployment-android.html
https://doc.qt.io/qt-6/ios.html
